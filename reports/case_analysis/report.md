# 案例分析题模块开发报告

日期：2026-11-12  
范围：新增独立案例分析题模块；复用现有 OCR、检索、DeepSeek 客户端和预算保护。未修改原始 PDF、页码映射、审核状态、教材向量或选择题自动判断逻辑。

## 1. 页面与 OCR

- 页面新增第三个标签页：`🧩 案例分析题`。
- 支持手动输入/粘贴文字，以及多张 PNG/JPG/JPEG 截图。
- 复用 `src/ocr.py::recognize_image()`，按上传顺序 OCR 并合并。
- 文件哈希去重，页面 rerun 不重复 OCR；新图片追加到已有案例文本，不静默覆盖用户编辑；部分截图失败时保留其他成功识别内容并提示；空图片、格式不支持、OCR 失败都有明确提示；OCR 只填入可编辑文本框，不自动提交、不调用 DeepSeek。
- 独立“清空案例”：清除案例文字、设问、上传哈希、OCR/答案状态；递增案例 uploader epoch，允许重新上传同一图片；不影响简答题、选择题、模式、AI 开关或预算。

## 2. 案例理解与多设问拆分

`src/case_solver.py::parse_case_questions()` 使用本地规则，不调用模型：

- 支持 `（1）`、`(1)`、`①②③`、`1.`、`1、`、`问题一`、`第1问`；
- 支持无编号问句（按问号切分）；
- 每个候选必须具有设问语气/任务词，避免把“2019年事故”等事件编号当成设问；
- 保留案例背景；
- 编号不连续、OCR 断行/缺少问号时提示“设问可能不完整”；
- 未识别到设问时提示用户手动填写，不擅自遗漏。

页面展示当前设问数量、每行一个设问的可编辑文本框；可修改、增加、删除、拆分、合并；用户手动编辑后，新截图不会静默覆盖设问；“重新识别设问”按钮用于显式更新。

## 3. 逐问检索

- 每个设问使用“设问文本 + 案例关键事实词”检索，不把整篇长案例作为唯一 BM25 查询。
- 默认 `expanded` 检索，复用现有双版本 PPT、教材补充、相关性/来源机制。
- 每个设问单独检索；相同证据去重并记录关联设问。
- 证据保留真实文件名、物理页码、审核状态。
- 无相关 PPT 时证据列表为空，模型可补充通用知识，但不得编造课件引用。

## 4. 一次 DeepSeek 生成全部设问

`src/case_solver.py::solve_case()`：

- 先构造完整案例、全部设问、逐问证据；
- 在调用前检查总字符数，超出 `max_input_chars` 直接报错，不截断、不调用；
- 一次 `client.chat` 生成全部答案；
- JSON 结构包含 `index`、`question`、`answer`、`citations`、`insufficient`；
- 每个答案要求结合案例事实和工程伦理理论，区分已知事实/推断/证据不足，只引用实际证据编号；
- API 失败、未授权、空/非法 JSON、超长输入均保留案例和检索证据，不伪造答案。

## 5. 本地完整性检查

生成后检查：

- 答案数量必须等于设问数量；
- `index` 必须从 1 开始、顺序一致；
- 每个答案正文非空；
- 引用编号必须存在；
- 任何缺失/错序/非法引用都标记 `incomplete`，页面显示错误，未静默通过。

答案按设问编号逐一展示；不完整的设问会显示“本地完整性检查：缺少该设问答案”。

## 6. 页面展示与移动端

- 默认混合模式，一次提交最多一次 DeepSeek 调用。
- 优先展示“案例分析考试作答”，每个设问独立编号。
- 详细证据、模型原始输出、案例原文、设问顺序放入折叠区。
- 支持复制/下载完整案例分析答案。
- 上传、案例文本、设问、提交、清空均为单列全宽。
- OCR、检索/生成均有进度提示。
- 简答题/选择题布局未回退。

## 8. 人工验收

```sh
cd /Users/along/Projects/Engineering-Ethics-RAG
source .venv/bin/activate
streamlit run app.py --server.address 127.0.0.1 --browser.gatherUsageStats false
```

1. 打开“案例分析题”标签页。
2. 上传三张案例截图（PNG/JPG/JPEG），确认显示 OCR 进度、按顺序合并、部分失败时保留其他内容。
3. 核对案例文字和“当前设问数量：3”。
4. 修改一个设问，确认修改后的设问参与检索。
5. 点击“重新识别设问”可显式恢复规则识别结果。
6. 点击“提交案例分析”：一次进度、答案按设问1/2/3分别展示；缺少/错序时显示完整性警告。
7. 查看折叠区：参考课件文件名、物理页码、审核状态、模型原始诊断，可复制/下载完整答案。
8. 点击“清空案例”：案例/设问/上传/答案清空；简答题和选择题内容不变；可重新上传同一图片。
9. 手机宽度确认单列、无横向滚动。
10. 本地关闭 AI 时案例不会调用模型，只保留证据和错误提示。

## 9. 剩余风险

- 设问拆分是规则法；复杂 OCR、跨页断行、事件编号与设问混排仍可能误判，页面提供手动编辑/确认。
- 逐问检索使用现有 retriever；若某设问无相关证据，模型使用通用知识，答案不会伪装成课件依据。
- 当前只检查答案数量/顺序/引用编号，未做逐句事实核验；案例分析答案仍需人工复核。
- 一次生成全部答案可能导致单次输出较长；超长输入会在调用前提示，不截断。
- 本阶段 OCR/API 全部 Mock，未调用真实 DeepSeek；真实模型 JSON 兼容性和答案质量需本机验收。
- 未读取/输出 API Key；未修改原始 PDF、页码映射、审核状态或教材向量。
- 未自动 git add/commit/push。
- 工作区快照：`backups/case_analysis_20261112-191739/`。
