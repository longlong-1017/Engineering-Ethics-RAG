## 1. 算法修改

### 1.1 可解释综合评分

每个候选证据保存 `score_breakdown`：

```text
relevance     与设问/检索 query 的直接相关度
theory_match  理论关键词匹配
definition    是否包含定义/原则/框架/责任等理论表述
same_case     是否为当前案例的直接分析
version       新版 PPT=1.0，旧版=0.5，教材/其他=0.2
review        严格审核=1.0，否则=0.3
```

综合分：

```text
0.35 * relevance
+ 0.25 * theory_match
+ 0.15 * definition
+ 0.15 * same_case
+ 0.05 * version
+ 0.05 * review
```

- 相关性/理论匹配优先；版本只在同类型/近似重复时作为排序补充。
- 高相关旧版理论可以排在不相关新版前面。
- 页面证据区显示评分项，便于调试。

### 1.2 四类证据

- `theory`：理论依据；
- `same_case_analysis`：老师 PPT 对**当前案例**的直接分析；
- `similar_case`：其他工程案例，仅类比；
- `background`：教材/一般背景。

当前案例识别：

- 从案例文本提取事件名/主体名，如“挑战者号”；
- 只有当前案例名称/主体出现时，才归为 `same_case_analysis` 或当前案例背景；
- 不能仅凭“安全事故”等通用词认定为当前案例；
- p10 类案例介绍若没有理论分析，归为 `background`；
- p66 类“挑战者号工程师职业责任”归为 `same_case_analysis`。

### 1.3 新旧 PPT 去重

- 文本规范化去除 OCR 空格、换行、标点；
- 长文本相似度 >= 0.96 才合并，避免不同理论仅因共享“安全/责任”被误合并；
- 近似重复保留**新版**为主证据；
- 合并旧版来源到 `sources`，页面和复制答案显示“合并来源”；
- 不删除原始知识库、不修改审核状态；
- 本次检索结果内的去重，不影响全库。

### 1.4 理论漏召回补充

- 从设问识别理论需求；
- 初始理论 query 与事实 query 分开，理论 query 不塞入事故专有细节；
- 检查理论需求是否被候选覆盖；
- 缺失时最多对每个设问补充 2 个本地查询（不调用 DeepSeek）；
- 同义词扩展：
  - 风险正常化 → 异常正常化、风险认知、组织风险文化、组织决策；
  - 可接受风险 → 风险容忍、风险接受、风险评价、风险决策；
  - 职业责任 → 工程师责任、社会伦理责任、公众安全；
  - 安全原则 → 安全优先、生命价值、风险防范。
- 最终仍无直接证据，明确提示“该理论缺少直接课件依据”，不把类似案例冒充理论。

### 1.5 数量与预算

- 每问最多 4 条，优先 `same_case_analysis` / `theory` / `background` / `similar_case`；
- 低相关类似案例和背景优先裁减；
- 共享证据只保留一次，记录多个关联设问；
- 输入预算不足时按类型/评分移除低优先级证据，并记录“未截断正文”的移除原因；
- 最终在所有裁剪完成后重新分配 S1、S2……，页面、Prompt、答案引用使用同一编号。

对应设问：

| 设问 | 主要证据 | 理由 |

### 检索前后关键差异

- 4 问从“全部理论不足”变为至少 1 条理论依据 + 本题案例直接分析；
- 当前案例分析优先于其他事故；
- 理论 query 不含挑战者号/1986，避免校准器误过滤；
- 每问最多 4 条，减少低相关教材/类似事故占据。
- 风险正常化仍是缺口：现有 PPT 没有足够直接解释，页面明确提示，而不是用“风险评估/责任”关键词强行冒充。

## 5. 被过滤/降权/去重证据说明

- 近似重复的新旧理论：保留新版主证据，旧版进入合并来源，不重复占据 S 位；
- 教材/背景：优先级低于理论/本题案例，只有未挤占高价值证据时才保留；
- 其他事故：`similar_case` 优先级最低，只作类比；
- 低相关候选：排序/预算裁剪时移除，并记录原因；
- 不同理论即使共享“安全/责任”等词，只要文本相似度不足，不合并。
