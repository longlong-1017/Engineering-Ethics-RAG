# 第八阶段根因报告：真实 DeepSeek 答案被事实校验反复拒绝

日期：2026-11-08  
项目：`/Users/along/Projects/Engineering-Ethics-RAG`

## 1. 检查范围

- `src/qa.py`：API 调用、结构化解析、回退决策
- `src/structured_answer.py`：JSON 解析、结构校验、事实校验、渲染
- `src/citations.py`：词项/数字/引用支持检查
- `src/evidence.py`：检索证据规划
- `src/app.py`：答案展示与 API 诊断

## 2. 当前调用链

```text
DeepSeek 返回结构化 JSON
      ↓
parse_structured_answer()
      ↓
validate_structured_answer()
      ↓
ok → VERIFIED（正常展示）
not ok → qa._api_answer() 直接回退本地摘录
```

关键问题：**校验结果只有“完全通过”与“整篇回退”两种状态**。只要任何一条论述被词法校验拒绝，结构化答案就被丢弃，用户看不到 AI 答案。

## 3. 为什么真实 API 输出经常被拒绝

### 3.1 把“证据关键词覆盖”当成“事实真实性判断”

`assess_claim_support()` 主要检查：

- 数字是否出现在所引证据；
- 关键词覆盖率是否达到阈值；
- 是否存在未知长词/限定词；
- 每页引用是否与论述有词项重合。

这些是**风险检测**，不是严格语义蕴含判断。真实模型会使用：

- 同义词、上下位词、自然改写；
- 概括性连接句；
- 多页合并后的新表述；
- 合理的考试式总结。

词项覆盖不足并不等于事实错误；但当前实现会把它当成事实错误，直接拒绝整篇。

### 3.2 任何一条失败导致整篇回退

`validate_structured_answer()` 收集所有 points 的错误；`qa._api_answer()` 只要 `not ok` 就调用 `_local_answer()`。

结果：

- 11 条论述中 1 条词法不匹配 → 另外 10 条真实 AI 内容也消失；
- 用户只看到离线摘录；
- 模型已消耗的 token 没有产生可用界面价值。

### 3.3 结构解析失败与事实校验失败没有区分

当前：

- JSON 解析失败；
- 引用编号不存在；
- 数字不一致；
- 正常总结词项覆盖不足；

都可能走同一“回退本地”路径。用户无法区分：

- 模型没有返回可用答案；
- 模型返回了答案，但部分事实未被严格核验。

### 3.4 词法阈值对真实自然语言过严

`strict_unknown=True` 对 points 要求所有未知词都有证据。Mock 测试通常直接复用原文词句，能通过；真实模型会自然会改写，例如：

- 把“环境工程中的社会公正”写成“社会公平”；
- 把“生产安全、公共安全、生态安全”概括为“工程安全”；
- 用“这表明”“因此”等连接语。

Mock 通过、真实失败的核心原因是：**测试数据与真实模型输出分布不同**。Mock 使用了贴近原文的短句，而真实 API 输出更长、更自然、更具概括性。

### 3.5 缺少“未经核验草稿”展示层

`app.py` 只有：

- DeepSeek 成功；
- 本地摘录；
- 资料不足/错误。

没有“AI 已生成，但未通过严格校验”的展示状态，因此只能回退。

## 4. 哪些是模型无依据生成，哪些是校验器误拒绝

### 应继续拒绝/标记风险

- 不存在或未提供的 `[S#]`；
- 与所引证据不一致的数字、金额、年份、人数；
- 明显新增的主体、地点、事故、人物；
- 无依据的“所有/必然/冲突/出售/泄露”等强限定或行动；
- 编号列表项完全没有引用；
- 模型自行生成 PDF 文件名或页码。

### 更可能是校验器误拒绝

- 正常同义改写、语序调整；
- “结论：”“综上所述”等总结；
- 多页证据合并后的概括；
- 非关键连接词和概括词；
- 一条论述覆盖多个证据页，但每页只贡献部分信息；
- 真实考试式总结，虽非逐字复述但有引用支持。

## 5. 架构修复方向

引入三态：

| 状态 | 含义 | 展示 |
|---|---|---|
| `VERIFIED` | 结构、引用、数字、关键事实均通过 | 结构化答案 + 真实 PDF 引用 + 已验证标记 |
| `UNVERIFIED` | AI 已返回可读答案，但存在未通过项 | 保留 AI 草稿；明确“未经逐条事实核验”；展示失败原因和检索证据；不把其引用当已验证依据 |
| `FAILED` | API 失败、JSON 不可解析、没有可用答案 | 离线摘录兜底；显示失败原因 |

原则：

1. 部分校验失败不再丢弃整篇 AI 答案；
2. 词法覆盖不足只标记风险，不直接判为事实错误；
3. 数字、非法引用、明显新增主体仍严格检查；
4. UNVERIFIED 不生成 `[S#]` 已验证引用，不关联 PDF 页码作为“依据”；
5. 检索到的课件证据单独展示，供用户人工复核；
6. 不关闭全部校验来伪造 VERIFIED。

## 6. 结论

当前问题不是某一个“结论：”或“第10条”导致的，而是：

- 词法风险检测与事实真伪判断混同；
- 全有/全无的二态回退；
- 缺少 UI 草稿状态；
- Mock 输出分布与真实模型输出分布不一致。

第八阶段将按三态架构重构展示和回退决策，并保留严格的引用合法性、数字和关键风险检查。
