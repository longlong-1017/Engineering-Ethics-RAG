# PDF数据质量检查报告

审查日期：2026-11-08（Asia/Shanghai）。阶段：数据质量审查，未开发任何 RAG 功能。

## 结论

**结构完整性通过；文本内容质量尚不适合将全部 JSON 直接作为完整、可信的 RAG 知识正文。**

10份 JSON 与10份源 PDF 一一对应，607页全部与当前解析器重新提取结果逐字符一致，文件名、物理页码和文档SHA-256对应正确。但“重新提取一致”只证明存储与解析器一致，不能证明没有漏字、错序或隐藏文字。

本次助手实际查看了16个无文本页PNG和30个分层随机有文本页PNG。随机样本中8页发现明显文本遗漏、阅读顺序或可见性异常，其余22页主要标题与正文基本对应。该结果不是人工签核、逐字校勘或全体607页的视觉验收，不可用作总体错误率估计。

建议先处理已确认的正文缺失和顺序问题，再复核风险页、制定图像与重复内容取舍策略，之后才进入知识库构建阶段。本次没有实施清洗、补录、OCR或入库。

## 检查方法与边界

- 使用项目 Python 3.12.15、PyMuPDF 1.26.7；未安装新依赖、OCR、LangChain、ChromaDB，未调用在线AI服务。
- 程序核对UTF-8 JSON可读性、版本、文件集合、document_id内容哈希、文档和页记录文件名/ID、页数、连续1起物理页码，以及每页text与原PDF的重新提取结果。
- 原PDF及原10份JSON在开始和结束均计算SHA-256；比较结果全部不变。原始记录包含的warning状态予以保留。
- 用本地Poppler pdftoppm渲染120 DPI PNG；每张PNG由-f/-l指定原PDF物理页，预览文件名为“文件编号-p物理页码”。不以印刷页码或页标签替代物理页码。
- 分层随机抽查：固定种子20261108，每份PDF从有非空文本的页面中抽3页，共30页（591个有文本页的5.08%）。按文件名排序后抽样，可复现。
- 视觉笔记来自本次助手实际打开PNG后的图像与JSON文本对照；没有人类审查者参与。未抽中的页面只做程序检查，不能标记为视觉正常。
- 短文本：非空且非空白字符少于30，属于候选，不等于错误。乱码初筛检测U+FFFD、私用区/代理字符、非换行制表控制字符、(cid:数字)；这些指标不能发现所有合理汉字间的错映射或缺词。
- 顺序风险：至少8个非空白字符的并排文本块有超过10点纵向重叠且横向分离超过10点；或非空白字符至少80且短行比例超过35%。不能检出全部错序，不能据此确认错序。
- 图像/图表/公式风险：排除每文档至少一半页面重复出现的图像后，剩余图像面积占比至少12%，或矢量路径至少10条，或常见数学/希腊符号至少2个。重复图像只是模板候选，不保证无信息；小图、字体轮廓、低路径图和图片内公式仍可能漏报。
- 初筛曾因重复背景图而将607页全部标记图像风险；已在汇总阶段校正，最终统计以 reviewed_page_metrics.csv 为准。audit_results.json和page_metrics.csv为保留的原始初筛证据，不能把其607页候选解释为607页均丢失图表。
- 重复候选：去掉空白、标点、数字后的文本至少40字符且相同；近似重复使用至少80字符的5-gram集合Jaccard>=0.85且<1。去数字可能合并不同数值页面，因此不自动去重。重复行统计限至少6字符、出现至少10页。
