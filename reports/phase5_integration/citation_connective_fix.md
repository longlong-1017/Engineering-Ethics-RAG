# 补充修复：依据/根据资料/综上所述等引用指针被误判为事实结论

日期：2026-11-08  
问题来源：真实 DeepSeek 返回正常答案后，系统报：

> 结论与所引证据的关键词覆盖不足（0%）；结论包含所引证据未支持的关键词：依据；引用 S1 与该条结论无实质重合。

随后回退本地摘录。

## 根因

模型在正常答案末尾附加了引用说明行，例如：

```text
工程风险的技术因素包括：
1. 零部件老化会导致系统功能失调…… [S1]
2. 控制系统失灵会带来事故隐患…… [S1]
3. 非线性作用会引发安全隐患…… [S1]
依据：[S1]
```

`src/citations.py` 把 `依据：[S1]` 当成一条带引用的独立事实结论：

- 去掉引用后得到 `依据`；
- 关键词只有 `依据`，所引页中没有该词；
- 关键词覆盖率 0%；
- 引用页与“依据”无实质重合；
- 整份答案被拒绝。

这是句子结构识别问题，不是模型引用格式错误。`依据/根据资料/综上所述` 在这类位置是**引用指针或连接语**，不是事实结论。

## 修复

修改 `src/citations.py`：

1. 新增 `CONNECTIVE_PREFIX_RE` 和 `_strip_connectives()`：
   - 只剥离句首的“依据课件/根据资料/综上所述/总之/由此可见/参考来源/资料来源/出处/说明”等非事实连接语；
   - 不把“依据/根据”加入全局停用词；
   - 不剥离“依据合同”“根据合同”等可能是真实事实的内容。
2. 新增 `_is_citation_pointer()`：
   - `依据：[S1]`、`依据课件：[S1]`、`根据资料 [S1]`、`综上所述 [S1]` 等只有指针/连接语、没有事实内容的行被忽略；
   - 只有指针、没有任何事实结论的答案仍会报“未包含任何可核验的 [S#] 引用”，不会被当作有效答案。
3. 先剥离连接语，再对剩余事实做校验：
   - `依据课件，工程风险包括技术因素。 [S1]`：剥离后校验“工程风险包括技术因素”；
   - `根据资料，事故造成12人死亡…… [S1]`：剥离后仍校验数字；
   - `依据合同，所有风险都由承包商承担。 [S1]`：不剥离，仍按事实校验，证据不支持时拒绝。
4. 保留列表前缀、圈号、全角编号识别：
   - `①拒绝 [S1]`、`１. 拒绝 [S1]` 不会被当成事实数字；
   - 未引用列表条目仍拒绝。
5. 保留原有引用编号、数字、关键词覆盖、多页支持、未知实体、限定词检查；**没有关闭引用校验**。

## 真实语料 + Mock 复现

使用真实 `processed_v3` 检索与 `FakeClient`（虚构密钥）重放用户结构：

```text
provider= deepseek
status= ok
api_outcome= accepted
api_reason= API已返回且引用校验通过（支持准确归纳）。
citations= [('02工程伦理第三讲工程中的风险、责任与安全(ver1.1).pdf', 8)]
```

答案末尾的 `依据：[S1]` 被正确忽略，三条事实列表均通过引用校验；没有回退。

## 反向测试

- 只有 `依据：[S1]`、没有事实结论 → 拒绝（“未包含任何可核验的 [S#] 引用”）。
- `根据资料，事故造成99人死亡…… [S1]` → 拒绝（数字未在所引证据出现）。
- `依据合同，所有风险都由承包商承担。 [S1]` → 拒绝（并非全局忽略“依据”）。
- 引导语后某条列表结论无引用 → 拒绝。
- `事故造成12人死亡：` / `工程风险会导致严重后果：` 无引用 → 拒绝。
- 多页引用、同义改写、数字题、简答题、案例分析继续通过。
