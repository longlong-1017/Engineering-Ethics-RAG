# Engineering-Ethics-RAG 第三阶段修复与验收报告

日期：2026-11-08（Asia/Shanghai）。全部复用 `.venv` Python 3.12.15；未安装新依赖，未调用任何真实模型 API。

## 结论及适用范围

本轮解决了原30题中的严格范围无证据强答、定义类型误判和关键数字/列表截断。严格模式正确回答16题，对池内缺正文的14题提示资料不足；扩展模式30题核心内容均能从课件文字层摘录，16题有严格证据，14题仍须人工复核。

这是对**同一30题、同一课件文字层、同一评分标准**的复测，不是通用语义正确性证明，也不代表30题现实事实已获独立核实。尤其 E 类金额、C 类图片遗漏、未修复 B 类顺序等源数据问题没有在本轮消失。离线结果为完整原文摘录，仍可能偏长，尚不是模型综合答案。

## 独立审查与基线核实

先阅读 README、第二阶段报告及两张逐题表、检索/问答实现和测试，再以原代码重跑60次。`reports/phase3_work/before/raw_results.json` 的60条状态、答案、引用键与第二阶段原始结果逐条完全一致。原有102项测试全部通过，说明原测试未覆盖主要验收失败。

核实的原因：

- 原充分性判断仅看短语或关键词覆盖率，不能区分目录、相似事故、召开会议与会议结果。严格模式10/14无证据强答确实存在。
- “是什么”被一概作为直接定义请求，误伤“两种思路”“五种方式”“事故后果”等；有正文时也拒答。
- 原摘录采用首引用与后续引用不同配额、总计6句和340字符截断，且短编号项之后的结果句可能被丢弃。
- 引用编号合法、页码存在不等于内容支持。原扩展模式26/49引用达到原内容阈值；在线路径此前也只有编号检查。

## 实施的修复

1. 新增 `src/evidence.py`，独立于题库执行主体、关系和实质正文检查。按定义、列表、原因、事实和说明规划引用；不读取题号、金标页、预期事实或评分标签。
2. 检索排序增加主题和实质正文权重；在当前模式池内补充同文件、同标题的相邻续页。仍保持Top-6默认，定义题沿用原有最少10个候选设置；严格模式没有借用扩展池。
3. 问题分类先排除列表、原因、时间地点后果等请求，再识别真正定义；直接定义检查兼顾物理换行，防止标题与定义粘连导致拒答，同时不把子概念定义当作父概念定义。
4. 删除“相关页兜底作答”和旧句子/字符配额。保留完整段落、编号项、小数、单位、限定语，跨页内容按物理页排序。完整清单不再带入不必要的背景页；保留有必要的互补引用。
5. 实际正文仅来自所引页。`Answer.to_dict()` 输出 `evidence_checks`，可查看每个候选的主体/正文判断；搜索线索与实际引用分开。非严格引用带状态与已有审查说明。
6. 在线路径使用同一证据计划；只接受可逐条在所引正文定位的摘录。编号越界、未给引用、正文无法定位、追加无引用结论或数字改写都回退离线摘录。只用 FakeClient 测试了该路径，无真实API调用。该约束偏保守，任意语义改写不作自动放行。

以上是可审计的词法与结构规则，不具备一般自然语言蕴含能力。相同名称的不同事件、多层修饰、隐含指代、超过当前候选窗口的长列表仍可能出错，不能把本轮零强答率推广到任意新题。
